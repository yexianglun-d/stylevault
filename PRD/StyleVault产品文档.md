# StyleVault 产品文档

文档版本：v2.0

更新日期：2026-08-16

项目性质：个人工具 / 技术沉淀 / 开源友好 / 非商业化

上线目标：完整正式版上线，不做残缺 MVP。

## 1. 产品定位

StyleVault 是一个个人使用的前端设计风格图鉴和 AI 协作工具。它的核心目标不是展示好看的卡片，而是把模糊的审美判断转化成可复用、可复制、可交给 AI 执行的风格语言。

一句话定义：

> StyleVault 帮助全栈开发者建立前端设计风格认知，并把风格选择、风格拆解、CSS 片段和 AI Prompt 组织成一个可长期复用的个人知识库。

核心承诺：

- 写前端页面前，能快速选定适合页面类型的设计风格。
- 看到喜欢的设计时，能按结构化维度拆解它为什么好看。
- 与 AI 协作写前端时，不再只说“高级一点”“好看一点”，而是给出明确的风格名称、视觉特征、配色、排版、质感、动效和 CSS 方向。
- 风格数据既能被程序读取，也能被自己长期学习和复盘。

## 2. 产品边界

### 2.1 要做什么

- 建立 30 种以上前端设计风格的结构化风格库。
- 每种风格都提供实时 CSS 预览，而不是静态图片。
- 每种风格都按 7 个核心维度拆解：形状、排版、光影、空间、动效、色彩、质感。
- 支持风格浏览、搜索、筛选、详情查看、收藏、对比、推荐、复制、导出、学习训练。
- 支持把风格转换为 AI 编程工具可直接理解的 Prompt。
- 支持导出 CSS Variables 和 Tailwind 配置片段。
- 支持图片上传后的 AI 风格识别和人工校正。
- 数据层同时支持 JSON 机器数据源和 Markdown 学习笔记。
- 允许开源，但保持个人工具定位。

### 2.2 不做什么

- 不做用户系统。
- 不做社区、评论、点赞、关注。
- 不做商业化和付费功能。
- 不做完整 UI 组件库。
- 不做在线代码编辑器。
- 不做团队协作。
- 不依赖他人图片素材作为核心内容。
- 不追求运营增长，不把功能设计成平台型产品。

## 3. 目标用户

第一用户就是项目作者本人：

- 主要身份：全栈开发者。
- 当前短板：前端审美、风格判断、专业设计术语、CSS 风格沉淀。
- 高频场景：用 AI 写登录页、后台系统、仪表盘、官网、工具页、个人项目页面。
- 期望体验：打开工具后能快速选风格、复制 Prompt、导出 CSS 变量，然后让 AI 输出的页面第一次就接近预期。

潜在次级用户：

- 也经常用 AI 写前端的开发者。
- 想系统学习前端视觉风格的工程师。
- 想把设计风格结构化沉淀为知识库的个人创作者。

次级用户不影响产品范围。所有功能优先服务个人使用效率。

## 4. 核心问题

用 AI 写前端时常见的问题不是 AI 不会写，而是人与 AI 之间的风格描述颗粒度不一致。

|描述层级|模糊表达|StyleVault 目标表达|
|---|---|---|
|风格名称|好看一点 / 高级一点|Glassmorphism 玻璃拟态|
|形态特征|圆润一点 / 有质感|大圆角、柔和弥散阴影、半透明磨砂质感|
|配色|蓝色系 / 暗一点|背景 #0F172A，主色 #6366F1，强调色 #22D3EE|
|排版|字体大气一点|无衬线字体、强标题层级、紧凑信息密度|
|动效|动画流畅点|300ms ease-out，hover 时 scale(1.02) 和阴影增强|
|实现方式|做出这个感觉|CSS Variables、backdrop-filter、box-shadow、border token|

StyleVault 的价值是填平这条鸿沟，让审美判断变成可复制、可验证、可训练的结构化资产。

## 5. 完整上线定义

本项目不以 MVP 上线。正式上线必须满足以下条件：

1. 风格库不少于 30 种，每种风格的数据完整。
2. 每种风格都有可视化 CSS 预览，并且不是空壳或静态截图。
3. 每种风格都有 AI Prompt、CSS 片段、配色、适用场景和 7 维度拆解。
4. 支持浏览、搜索、分类筛选、标签筛选、收藏、对比。
5. 支持按页面类型推荐风格。
6. 支持导出 CSS Variables 和 Tailwind 主题片段。
7. 支持图片上传后的 AI 风格识别，并允许人工确认与修正。
8. 支持学习训练模式，用来训练风格识别能力。
9. JSON 数据结构稳定，Markdown 学习笔记结构统一。
10. 所有复制和导出内容都能直接用于 AI 编程工具。
11. 桌面端和移动端都可用，桌面端体验优先。
12. 可静态部署，刷新不丢失收藏和本地学习记录。
13. 开源仓库不包含侵权图片、私密 Prompt、真实项目截图或未授权素材。

## 8. 核心用户流程

### 8.1 用 AI 写页面前选风格

触发：准备让 AI 写一个具体页面。

流程：

1. 进入“页面推荐”。
2. 选择页面类型，例如登录页、仪表盘、SaaS 官网、个人作品集、数据看板。
3. 选择偏好，例如暗色、极简、科技感、质感、复古、强视觉冲击。
4. 系统推荐 3 到 5 种风格。
5. 用户打开详情查看预览和适用理由。
6. 用户复制 AI Prompt 或导出 CSS Variables。
7. 用户把内容粘贴给 AI 编程工具。

成功标准：

- 用户在 3 分钟内确定一个主风格。
- 复制出来的 Prompt 不需要再次手工组织风格描述。
- AI 首次生成结果的风格方向基本正确。

### 8.2 看到喜欢的设计后拆解风格

触发：用户看到一个喜欢的界面截图。

流程：

1. 进入“图片识别”。
2. 上传截图。
3. AI 返回候选风格、置信度、相似理由和 7 维度拆解。
4. 用户选择最接近的风格，或手动修正识别结果。
5. 用户可以把结果保存为学习记录，或作为新风格草稿。

成功标准：

- 输出至少 3 个候选风格。
- 每个候选风格说明为什么像。
- 用户可以人工覆盖 AI 判断。
- 不把 AI 结果当成绝对结论，而是作为辅助拆解。

### 8.3 对比两个相似风格

触发：用户觉得两个风格都合适，但不知道差异。

流程：

1. 进入“风格对比”。
2. 选择风格 A 和风格 B。
3. 页面左右展示预览。
4. 下方展示 7 维度差异、配色差异、适用场景差异、CSS 实现差异。
5. 用户复制“差异描述 Prompt”，用于要求 AI 从一种风格调整到另一种风格。

成功标准：

- 不只展示两个卡片，而是明确指出差异。
- 差异描述可以直接用于 AI 微调。

### 8.4 沉淀常用风格

触发：用户在多个项目里反复使用某些风格。

流程：

1. 用户在风格卡片或详情页点击收藏。
2. 收藏夹按最近使用、分类、页面类型展示。
3. 用户可以给收藏风格添加个人备注。
4. 用户可以一键复制收藏风格的常用 Prompt。

成功标准：

- 收藏数据本地持久化。
- 刷新页面后不丢失。
- 收藏夹能减少重复搜索。

### 8.5 训练自己的风格识别能力

触发：用户想提升审美和风格拆解能力。

流程：

1. 进入“学习训练”。
2. 系统随机出题，题型包括：
   - 给风格预览猜风格名。
   - 给 7 维度描述猜风格名。
   - 给两个风格选择差异维度。
   - 给页面类型选择合适风格。
3. 用户答题后显示正确答案、解析和相关 CSS 线索。
4. 系统记录正确率、易错风格和最近训练记录。

成功标准：

- 训练不是娱乐题，而是帮助用户形成设计语言。
- 每道题都必须有解析。
- 学习结果能反映用户对风格识别是否进步。

## 9. 页面规格

### 9.1 风格图鉴页

目标：快速浏览所有风格，建立视觉索引。

必须包含：

- 搜索框。
- 分类筛选：minimal、texture、retro、future、experimental。
- 标签筛选。
- 页面类型筛选。
- 风格卡片网格。
- 每张卡片展示名称、英文名、分类、标签、迷你 CSS 预览、收藏按钮、对比按钮、复制 Prompt 按钮。
- 空状态和无结果状态。

交互要求：

- 点击卡片进入详情。
- 点击收藏不跳转。
- 点击对比可加入对比槽。
- 搜索和筛选可组合使用。
- 筛选结果数量实时显示。

### 9.2 风格详情页

目标：完整理解某一种风格，并把它用于真实项目。

必须包含：

- 大型实时预览。
- 风格基础信息：中文名、英文名、分类、标签、适用页面。
- 核心视觉特征。
- 7 维度形态特征。
- 配色方案和色值复制。
- AI Prompt。
- CSS 核心片段。
- CSS Variables。
- Tailwind 配置片段。
- 适用场景。
- 不适用场景。
- 相似风格和可对比风格。
- Markdown 学习笔记入口。

交互要求：

- 每个可复制区都有复制按钮和成功反馈。
- 预览支持桌面、移动、卡片、表单、仪表盘四种样例视图。
- 用户可以收藏、加入对比、进入混合器。

### 9.3 风格对比页

目标：帮助用户判断两个风格的差异和选择依据。

必须包含：

- 双风格选择器。
- 并排实时预览。
- 基础信息对比。
- 7 维度差异表。
- 配色差异。
- CSS 实现差异。
- 适用场景差异。
- AI 微调 Prompt。

交互要求：

- 支持交换左右风格。
- 支持从图鉴页快速带入对比。
- 支持复制差异描述。

### 9.4 页面推荐页

目标：根据页面类型和审美偏好，推荐适合的风格。

页面类型至少包含：

- 登录页
- 注册页
- SaaS 官网
- 个人作品集
- 后台管理系统
- 数据仪表盘
- AI 工具页
- 开发者工具页
- 移动端应用首页
- 营销活动页
- 定价页
- 文档站

用户输入：

- 页面类型。
- 明暗偏好。
- 信息密度。
- 视觉强度。
- 是否偏科技感。
- 是否偏质感。
- 是否需要强动效。

输出：

- 推荐 3 到 5 种风格。
- 每种风格给出适用理由。
- 每种风格给出风险提示，例如可读性、实现成本、审美疲劳。
- 一键生成页面 Prompt。

推荐规则：

- 初期使用本地规则，不依赖远程服务。
- 规则来自风格数据中的 `useCases`、`pageTypes`、`tags`、`density`、`visualIntensity`。
- 如果接入 AI，只能作为增强解释，不作为唯一推荐来源。

### 9.5 图片识别页

目标：辅助用户从截图中识别风格，而不是替代用户判断。

必须包含：

- 图片上传区域。
- 图片预览。
- AI 识别按钮。
- 候选风格列表。
- 7 维度拆解结果。
- 主色提取结果。
- 人工校正区域。
- 保存为学习记录或新风格草稿。

识别策略：

- 前端先做基础颜色分析：主色、背景色、亮度、对比度。
- AI 多模态负责风格归属、视觉语言拆解和相似风格解释。
- AI 输出必须可编辑。
- 不保存用户上传图片到远程仓库。

边界：

- 如果没有配置 AI Key，页面显示“手动拆解模式”。
- 手动拆解模式仍可上传图片、本地看图、填写 7 维度、关联已有风格。

### 9.6 风格混合器

目标：把 2 到 3 种风格融合成一个可执行的新风格方向。

输入：

- 选择 2 到 3 种已有风格。
- 设置每种风格权重。
- 选择主导维度，例如色彩来自 A，质感来自 B，排版来自 C。

输出：

- 融合风格名称建议。
- 融合风格描述。
- 7 维度融合结果。
- 配色建议。
- AI Prompt。
- CSS Variables 草案。

边界：

- 混合器输出默认是草稿，不自动进入正式风格库。
- 用户确认并补齐字段后，才能保存为新风格。

### 9.7 学习训练页

目标：量化用户对风格的识别和拆解能力。

必须包含：

- 训练题库。
- 答题界面。
- 答案解析。
- 正确率。
- 易错风格。
- 最近训练记录。
- 学习目标进度。

题型：

- 看预览猜风格。
- 看特征猜风格。
- 看配色猜风格。
- 看 CSS 片段猜风格。
- 对比两个风格找差异。
- 给页面类型选风格。

### 9.8 数据与导出页

目标：让风格资产可迁移、可复用、可开源。

必须包含：

- 导出全部风格 JSON。
- 导出单个风格 JSON。
- 导出 CSS Variables。
- 导出 Tailwind 配置片段。
- 导出 AI Prompt。
- 查看数据完整性检查结果。
- 查看 Markdown 学习笔记覆盖情况。

## 10. 风格分类与标签决策

正式版一级分类固定为 5 类：

|分类|说明|
|---|---|
|minimal|简约类，强调留白、秩序、克制和清晰度|
|texture|质感类，强调材质、阴影、拟物、玻璃、黏土、纸张等触感|
|retro|复古类，强调年代感、旧媒介、像素、印刷、怀旧视觉|
|future|未来类，强调科技感、霓虹、数据感、空间感和高对比|
|experimental|实验类，强调非常规排版、强视觉冲击、艺术化和反常规布局|

一级分类不继续膨胀。更细的描述使用标签完成。

标签示例：

- 暗色
- 浅色
- 高对比
- 低饱和
- 霓虹
- 毛玻璃
- 硬投影
- Bento
- SaaS
- 仪表盘
- 作品集
- 复古印刷
- 像素
- 全息
- 金属
- 黏土
- 极简
- 编辑器感

## 11. 形态特征规范

每种风格必须填写 7 个核心维度。

|维度|可选标签|说明|
|---|---|---|
|形状|直角 / 小圆角 / 大圆角 / 全圆角 / 圆形 / 不规则 / 有机曲线 / 像素化|元素边角和几何倾向|
|排版|无衬线 / 衬线 / 等宽 / 手写 / 装饰体 / 极端对比 / 均匀层级 / 大标题主导|字体、字号、字重、层级、对齐|
|光影|无阴影 / 柔和弥散 / 硬投影 / 长投影 / 内阴影 / 发光 / 金属高光 / 玻璃反光|阴影、高光、明暗关系|
|空间|极多留白 / 适中 / 紧凑 / 密集 / 扁平 / 多层深度 / 居中 / 分栏 / 网格 / 不对称|留白、间距、层叠和布局方式|
|动效|无 / 平滑缓动 / 弹性弹跳 / 机械步进 / 流体 / 快速 / 中速 / 慢速|运动风格、过渡速度、反馈方式|
|色彩|单色 / 双色 / 三色 / 多彩 / 渐变 / 低饱和 / 高饱和 / 冷色 / 暖色 / 对比 / 全息 / 金属|色彩数量、饱和度、色温和对比|
|质感|光滑 / 磨砂 / 粗糙 / 金属 / 玻璃 / 纸张 / 黏土 / 像素 / 无纹理 / 噪点 / 网格 / 条纹 / 细线 / 粗线 / 发光边框|表面触感和纹理语言|

可选增强维度：

|维度|说明|
|---|---|
|组件形态|卡片式、列表式、仪表盘式、编辑器式、营销页式、工具面板式|
|信息密度|低密度、中密度、高密度|
|视觉强度|克制、中等、强冲击|

增强维度用于推荐和筛选，不强制影响核心 7 维度。

## 12. 风格数据规范

### 12.1 数据源策略

StyleVault 同时使用 JSON 和 Markdown：

- JSON 是程序读取的唯一结构化数据源。
- Markdown 是个人学习、解释、复盘和开源阅读材料。
- 两者通过同一个 `id` 关联。
- JSON 字段必须完整，Markdown 可以写得更像文章。

推荐目录：

```text

data/page-type-rules.json
data/training-records.schema.json
docs/styles/glassmorphism.md
docs/styles/brutalism.md
docs/styles/neumorphism.md
```

## 13. Markdown 笔记规范

每种风格必须有对应 Markdown 笔记，路径为：

```text
docs/styles/{style-id}.md
```

笔记结构：

```markdown
# 风格中文名 / English Name

## 一句话理解

## 适合什么页面

## 不适合什么页面

## 7 维度拆解

## CSS 实现要点

## AI Prompt 写法

## 常见错误

## 我的使用记录
```

Markdown 不作为程序唯一数据源，避免自由文本导致程序读取不稳定。

## 14. AI 协作能力

### 14.1 AI Prompt 生成

每个风格至少提供 3 类 Prompt：

1. 简短关键词版：适合快速粘贴。
2. 完整实现版：包含页面类型、配色、布局、动效和 CSS 要求。
3. 微调差异版：用于从一种风格调整到另一种风格。

Prompt 必须避免空泛词：

- 避免只写“高级”“现代”“好看”。
- 必须包含可执行词：颜色、圆角、阴影、布局密度、字体倾向、动效速度、CSS 属性方向。

### 14.2 图片识别 AI

图片识别使用 AI 多模态能力，但不作为基础功能的唯一依赖。

配置要求：

- 没有 AI Key 时，图片识别页降级为手动拆解工具。
- 有 AI Key 时，AI 输出候选风格、相似度解释、7 维度拆解、Prompt 草稿。
- AI 输出必须支持编辑和保存。
- API Key 不写入代码仓库。

### 14.3 AI 输出格式

AI 风格识别结果统一为：

```json
{
  "candidates": [
    {
      "styleId": "glassmorphism",
      "confidence": 0.82,
      "reason": "截图中存在半透明面板、背景模糊、冷色渐变和柔和高光边框。",
      "matchedDimensions": ["texture", "lighting", "color", "space"]
    }
  ],
  "extractedPalette": [
    { "hex": "#0F172A", "role": "background" }
  ],
  "formCharacteristicsDraft": {},
  "promptDraft": ""
}
```

## 15. 推荐规则

页面推荐初期使用本地规则，保证不用 AI 也能稳定工作。

### 15.1 页面类型字段

每种风格通过 `pageTypes` 声明适合页面类型。

页面类型枚举：

```text
login
register
saas-landing
portfolio
admin
dashboard
ai-tool
developer-tool
mobile-home
campaign
pricing
docs
```

### 15.2 推荐评分

每个候选风格计算推荐分：

```text
score =
  页面类型匹配分
  + 标签匹配分
  + 明暗偏好分
  + 信息密度匹配分
  + 视觉强度匹配分
  - 实现成本惩罚
```

推荐结果必须包含：

- 推荐理由。
- 风险提醒。
- 最适合的页面区块。
- 可复制 Prompt。

## 16. 本地存储

## 17. 技术实现原则

### 17.1 技术栈

正式版建议锁定为：

- 前端：Vue 3 或 React，二选一后不频繁切换。
- 样式：原生 CSS + CSS Variables。
- 数据：JSON。
- 学习笔记：Markdown。
- 部署：静态部署，支持 GitHub Pages / Vercel / 本地运行。

如果优先考虑个人快速维护，建议使用：

```text
Vue 3 + Vite + TypeScript + CSS Variables
```

选择理由：

- 适合单页工具。
- 数据驱动 UI 简单。
- 静态部署方便。
- 后续可以轻松拆组件。

### 17.2 预览实现

预览必须基于 CSS 和 HTML 结构渲染，不能只放图片。

每种风格至少提供 4 个预览场景：

- 卡片
- 表单
- 仪表盘
- 营销区块

预览目标不是做完整页面，而是展示该风格在真实 UI 元素上的表现。

### 17.3 复制和导出

复制内容必须可直接使用。

复制项：

- AI 关键词。
- 完整 Prompt。
- 配色 HEX。
- 单个 CSS 片段。
- 全量 CSS Variables。
- Tailwind 主题片段。
- 对比差异 Prompt。

复制成功必须有明确反馈。

## 18. 开源策略

项目建议开源，但开源目标是作品展示和知识沉淀，不是运营社区。

可以开源：

- 项目代码。
- 风格数据结构。
- 基础风格数据。
- 自写 CSS 片段。
- 自写 Markdown 笔记。
- README 和使用说明。

不应开源：

- 未授权设计截图。
- 真实商业项目截图。
- 私密 Prompt。
- API Key。
- 付费素材。
- 来源不明图片。

开源前必须检查：

- README 写明项目定位。
- LICENSE 明确。
- `.env.example` 提供变量示例。
- `.gitignore` 排除本地环境文件。
- 图片识别功能不默认暴露任何密钥。

## 19. 学习效果量化

学习效果不做复杂评估，聚焦“是否让 AI 写前端更跟手”。

核心指标：

|指标|目标|
|---|---|
|选风格耗时|常见页面 3 分钟内确定主风格|
|AI 微调轮次|常见页面生成后 0 到 1 次风格微调|
|风格识别正确率|随机 10 道训练题答对 7 道以上|
|风格拆解完整度|看到一个界面能说出至少 5 个维度特征|
|复用次数|每月至少 1 个真实页面使用 StyleVault 的 Prompt 或 CSS|
|风格库增长|长期扩展到 50 种以上|

学习记录只服务自己，不做排行榜。

## 20. 正式上线验收清单

### 20.1 内容验收

- 至少 30 种风格数据完整。
- 每种风格都有 Markdown 学习笔记。
- 每种风格都有 7 维度拆解。
- 每种风格都有配色、Prompt、CSS Snippet、CSS Variables、Tailwind 片段。
- 每种风格都有适用场景和不适用场景。
- 每种风格都有至少 5 个标签。

### 20.2 功能验收

- 图鉴页可搜索、筛选、收藏、加入对比。
- 详情页所有复制按钮可用。
- 对比页可选择任意两种风格并展示差异。
- 页面推荐页能根据页面类型输出推荐结果。
- 图片识别页在无 AI Key 时可手动拆解，在有 AI Key 时可调用识别。
- 混合器能生成融合 Prompt 和 CSS Variables 草案。
- 学习训练页能出题、判题、显示解析、记录结果。
- 数据与导出页能导出 JSON、CSS Variables 和 Tailwind 片段。

### 20.3 体验验收

- 桌面端布局稳定，适合长时间浏览和对比。
- 移动端可完成浏览、详情查看、复制和收藏。
- 所有复制动作都有反馈。
- 空状态、加载状态、错误状态完整。
- 搜索无结果时给出清晰提示。
- 图片识别失败时不影响手动拆解。

### 20.4 技术验收

- 静态构建通过。
- 刷新页面不丢失本地收藏和学习记录。
- 数据字段有校验脚本或校验逻辑。
- 不提交 API Key。
- 不提交未授权素材。
- 所有风格预览非空白。
- 主流桌面浏览器可用。

## 21. 开发顺序

虽然目标是完整上线，但开发仍需要按依赖顺序推进。

推荐顺序：

1. 建立数据结构和 3 个样例风格。
2. 完成图鉴页、详情页、复制能力。
3. 扩展到 30 种完整风格数据。
4. 完成对比页。
5. 完成页面推荐规则。
6. 完成 CSS Variables 和 Tailwind 导出。
7. 完成收藏、本地记录和学习训练。
8. 完成风格混合器。
9. 完成图片识别和手动拆解模式。
10. 完成开源文档、数据校验、部署验收。

开发过程可以分阶段实现，但上线口径不拆成 MVP。只有验收清单全部完成，才称为正式上线。

## 22. 风险与处理

|风险|表现|处理|
|---|---|---|
|风格数据写得太泛|AI 输出仍然不跟手|每种风格必须包含 CSS 属性方向和具体视觉参数|
|分类越来越乱|新增风格不知道放哪里|一级分类固定，细分全部走标签|
|图片识别依赖 AI|没有 Key 时功能不可用|提供手动拆解模式|
|开源素材侵权|使用未授权截图|不把截图作为核心内容，预览全部用 CSS 自绘|
|功能过多导致开发拖延|长期无法上线|按开发顺序推进，但上线标准保持完整|
|Markdown 和 JSON 不一致|笔记和程序显示冲突|JSON 为准，Markdown 用 `id` 关联并作为学习解释|

## 23. 最终决策记录

1. 一级分类固定为 5 类：minimal、texture、retro、future、experimental。
2. 核心形态特征固定为 7 维度，组件形态、信息密度、视觉强度作为增强字段。
3. 图片识别接入 AI 多模态，但必须提供无 AI Key 的手动拆解模式。
4. JSON 和 Markdown 同时使用：JSON 给程序，Markdown 给学习。
5. 项目建议开源，但不做运营型开源项目。
6. 学习效果用选风格耗时、AI 微调轮次、训练正确率、真实复用次数衡量。
7. 项目不做 MVP，上线必须满足完整正式版验收清单。
